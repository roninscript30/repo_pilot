# Glossary

This page defines project-specific terms. Add terms once they become important enough that inconsistent interpretation would slow future work.

| Term | Meaning |
| --- | --- |
| Project memory | The repository's persistent engineering knowledge base and second brain. It is maintained for contributors and agents, not for end users. |
| Agent memory | The AI-focused working and historical memory area under [../agents/](../agents/). |
| Skill | A reusable workflow, convention, or project-specific capability stored under [../skills/](../skills/). |
| Decision record | A durable record of an architectural or engineering decision and the rationale behind it. |
| Repository operating platform | The intended product category: a unified engineering workspace for managing, understanding, and operating software repositories. |
| Provider | A Git hosting or repository service integration, such as GitHub, GitLab, Forgejo, or Gitea. |
| GitHub MVP | The first product version focused on GitHub authentication and repository management from a desktop interface. |
| Repository operation | A workflow that helps maintain, inspect, govern, release, diagnose, or collaborate on a repository. |
| Engineering insight | Derived information that helps developers understand repository health, activity, architecture, readiness, or productivity. |
| Desktop workspace | The intended interaction model for the MVP: a cohesive desktop interface for repository work rather than a simple website or API viewer. |
