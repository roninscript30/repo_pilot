# Skill: Repository Operating Platform Product Thinking

## Purpose

Evaluate product features against the project's long-term platform vision.

## Use When

- Scoping features.
- Reviewing UX direction.
- Deciding whether a capability belongs in the MVP or later roadmap.
- Preventing drift toward a narrow Git client, GitHub clone, or simple repository viewer.

## Workflow

1. Read [../../project/vision.md](../../project/vision.md), [../../project/mvp.md](../../project/mvp.md), and [../../project/philosophy.md](../../project/philosophy.md).
2. Define the repository operation or engineering workflow the feature improves.
3. Identify whether the feature helps users manage, collaborate on, understand, or operate repositories.
4. Prefer cohesive workflows over isolated data screens.
5. Confirm the feature strengthens the platform direction or intentionally serves the MVP foundation.
6. Record product rationale when it influences architecture or prioritization.

## Product Questions

- Does this help a developer or maintainer operate a repository more effectively?
- Does this turn data into useful context or just display API fields?
- Does this preserve the long-term multi-provider direction?
- Does this improve the desktop workspace experience?
- Is this foundational, or should it wait until the platform has stronger primitives?

## Quality Bar

- Features connect to a repository operation or engineering workflow.
- MVP decisions remain simple without narrowing the long-term product category.
- Product rationale is explicit when tradeoffs are made.
