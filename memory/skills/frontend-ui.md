## Purpose

Guide UI work for a desktop-first engineering platform.

## Principles

- Preserve transparency: show what repository operations do.
- Prefer information density with clarity over decorative complexity.
- Design for keyboard and mouse workflows first, while keeping layouts responsive.
- Support professional workflows with clear hierarchy, status, and navigation.
- Avoid generic dashboards that do not explain repository state.
- Make errors, loading states, and permissions explicit.
- Use accessible contrast, focus states, and semantic structure.

## Desktop Interface Expectations

- Navigation should support moving across repositories, workflows, and entities quickly.
- Dense views should remain scannable.
- Important repository state should be visible without excessive clicks.
- Destructive operations must be explicit and confirmable.
- AI-assisted UI should show reasoning, sources, and confidence where relevant.

## Future Design Areas
