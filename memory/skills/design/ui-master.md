# Skill: UI Master

## Purpose

Create polished, modern, professional desktop UI for a repository operating platform.

## Use When

- Designing screens, layouts, panels, navigation, tables, cards, charts, or repository workspace views.
- Reviewing visual quality.
- Turning raw repository data into a readable interface.
- Avoiding generic dashboard UI.

## Workflow

1. Start from the user workflow, not the component list.
2. Decide the screen hierarchy: primary action, core status, supporting details, secondary metadata.
3. Use density intentionally. Repository tools need information-rich UI without visual clutter.
4. Prefer strong alignment, clear grouping, readable typography, restrained color, and purposeful contrast.
5. Design empty, loading, error, permission, rate-limit, and partial-data states.
6. Make provider identity visible when useful without making the whole product feel GitHub-only.

## Repo Pilot UI Principles

- Feels like an engineering cockpit, not a marketing dashboard.
- Prioritizes clarity under information density.
- Shows repository status and workflow context quickly.
- Uses visual hierarchy to turn many API facts into decisions.
- Treats desktop space as an advantage.

## Quality Bar

- A maintainer can understand repository state at a glance.
- The UI remains useful with real-world noisy repositories.
- Visual design supports action, not decoration.
- Mobile responsiveness may matter later, but MVP priority is excellent desktop UX.
