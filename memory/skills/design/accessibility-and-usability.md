# Skill: Accessibility And Usability

## Purpose

Make Repo Pilot usable, readable, keyboard-friendly, and trustworthy for a broad range of developers.

## Use When

- Designing or reviewing UI.
- Adding keyboard shortcuts, tables, charts, dialogs, forms, or status indicators.
- Displaying dense repository data.
- Choosing colors, icons, or interaction patterns.

## Workflow

1. Ensure text and status information are readable without relying only on color.
2. Design keyboard navigation for primary workflows.
3. Use labels, descriptions, and predictable focus behavior.
4. Make tables and lists scannable with clear sorting, filtering, and empty states.
5. Provide useful error messages that explain cause and next action.
6. Test dense screens with realistic repository data.

## Repository UI Watchlist

- Workflow status colors must include text or icons.
- Branch, PR, and issue lists need clear states and filters.
- Charts need labels and fallback summaries.
- Auth and permission errors must be understandable.
- Keyboard users should be able to move through repository work without pointer-only traps.

## Quality Bar

- Core MVP workflows are usable with keyboard and screen-reader-friendly structure.
- Important state is perceivable through text, shape, or layout, not only color.
- Error states help users recover.
