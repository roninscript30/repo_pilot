# Skill: UX Master

## Purpose

Design repository workflows that feel coherent, fast, and useful for developers and maintainers.

## Use When

- Designing user journeys.
- Defining navigation and workspace flows.
- Converting MVP capabilities into user tasks.
- Reviewing whether a feature is actually useful or only displays data.

## Workflow

1. Identify the user role: individual developer, maintainer, reviewer, release owner, or project lead.
2. Define the job: manage, understand, collaborate, diagnose, release, or operate.
3. Map the shortest useful path through the workflow.
4. Decide what context must persist across screens.
5. Reduce mode switching between repositories, branches, issues, PRs, commits, releases, and workflows.
6. Design recovery paths for auth failures, missing permissions, empty repos, archived repos, and provider outages.

## Repo Pilot UX Principles

- Cohesive workflows beat isolated pages.
- Users should know where they are: provider, owner, repo, branch, workflow, and task.
- Important repository context should stay visible while users drill into details.
- Advanced insights should explain their evidence and limits.
- The product should feel trustworthy before it feels clever.

## Quality Bar

- The workflow reduces cognitive load for repository work.
- The interface helps users decide what to do next.
- Error and edge states are part of the design, not afterthoughts.
- The UX supports future multi-provider behavior without confusing MVP users.
