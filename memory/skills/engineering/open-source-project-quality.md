# Skill: Open-Source Project Quality

## Purpose

Maintain professional engineering standards so the repository itself demonstrates the quality expected from the platform.

## Use When

- Implementing features or refactors.
- Adding project structure, tooling, tests, or CI.
- Reviewing contributions.
- Updating contributor-facing or memory documentation.

## Workflow

1. Read [../../project/philosophy.md](../../project/philosophy.md) and relevant engineering memory.
2. Prefer simple, explicit, maintainable implementation choices.
3. Add or update tests when behavior is introduced.
4. Keep architecture boundaries visible.
5. Document new workflows and quality gates.
6. Preserve new durable knowledge in memory before handoff.

## Quality Bar

- The change improves maintainability, not just immediate functionality.
- Tooling and workflows are reproducible.
- Documentation and memory stay synchronized with implementation.
- The repository remains approachable for external contributors.
